# v1.0.5 migration guide: View construct consolidation

Schemas v1.0.5 consolidates the View construct into a dedicated `models/v1beta1/view`
package. This is a focused, narrow change - **no packages are removed, no major
breaking import path changes**.

## What changed in v1.0.5

### New: `models/v1beta1/view/view.go`

- `MesheryView` - full View struct with `core.Uuid`, `core.Map`, `core.Time`,
  `core.NullTime` fields
- `MesheryViewPage` - paginated view list with `[]MesheryViewWithLocation`
- `MesheryViewWithLocation` - view enriched with workspace/org context
- `ViewPayload` - create/update payload

### Modified: `models/v1beta1/workspace/workspace.go`

- `workspace.MesheryView` - now a **type alias** to
  `viewv1beta1.MesheryViewWithLocation` (backward compatible)
- `workspace.MesheryViewPage` - **removed** (use `view.MesheryViewPage` instead)
- `workspace.CorePage` - **added** as the canonical page alias; `workspace.Page`
  is unchanged and still compiles (both are `type X = string`)

### Modified: `models/v1beta1/pattern/pattern.go`

- **Removed** stub types: `MesheryView` (`map[string]interface{}`),
  `MesheryViewPage`, `ViewUpdatePayload`

### Modified: `models/v1beta2/design/design.go`

- **Removed** stub types: `MesheryView` (`map[string]interface{}`),
  `MesheryViewPage`, `ViewUpdatePayload`

### TypeScript

- New `typescript/generated/v1beta1/view/View.ts` and `ViewSchema.ts` with proper
  View types
- Updated `typescript/rtk/cloud.ts`: View endpoints now use the `View_views` cache
  tag (previously `Design_designs`); new `createView` and `deleteView` endpoints
  added
- Removed View stub types from `pattern/Pattern.ts` and `design/Design.ts`

## Migration guide for Go consumers

| Before (v1.0.4) | After (v1.0.5) | Notes |
|---|---|---|
| `workspace.MesheryView` | `workspace.MesheryView` or `view.MesheryViewWithLocation` | Type alias - existing code compiles. Prefer canonical import for clarity |
| `workspace.MesheryViewPage` | `view.MesheryViewPage` | **Removed** - must update import |
| `workspace.Page` | `workspace.Page` (or `workspace.CorePage`) | **Not** renamed or removed - `CorePage` was added alongside it; both still compile |
| `pattern.MesheryView` | `view.MesheryView` | Stub removed |
| `pattern.MesheryViewPage` | `view.MesheryViewPage` | Stub removed |
| `pattern.ViewUpdatePayload` | `view.ViewPayload` | Stub removed |
| `design.MesheryView` | `view.MesheryView` | Stub removed |
| `design.MesheryViewPage` | `view.MesheryViewPage` | Stub removed |
| `design.ViewUpdatePayload` | `view.ViewPayload` | Stub removed |

New import: `viewv1beta1 "github.com/meshery/schemas/models/v1beta1/view"`

## Migration guide for TypeScript consumers

| Before (v1.0.4) | After (v1.0.5) |
|---|---|
| View types from `v1beta1/pattern` or `v1beta2/design` | Import from `v1beta1/view/View` |
| RTK hooks with `Design_designs` tag for views | RTK hooks with `View_views` tag |
